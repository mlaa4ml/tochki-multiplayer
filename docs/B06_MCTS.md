# B06: эксперимент с MCTS (issue #29)

Это **отдельный эксперимент**. Основной поиск (`Engine.searchMove` в `gameEngine.js`) не меняется
и не заменяется. Тесты контракта правил A01 (`test/rules.js`, `test/fixtures/rules-v2.json`) не трогаются.
Прототип живёт в изолированном модуле `tools/mcts/` и использует только публичное API движка
(`createMatch`, `createSearchNode`, `isTransitionLegal`, снапшоты).

Результат документируется в любом случае, в том числе если он отрицательный.

## Почему MCTS, а не обучаемая policy/value

- Данных для обучения мало: реплеи A02 (#7) есть, но корпуса партий людей нужного объёма нет.
  Обучаемая сеть на таких данных почти наверняка переобучится, а честная оценка потребует
  отдельного «несожжённого» корпуса и для обучения, и для теста.
- MCTS (UCT) не требует обучения, поэтому вопрос «обучающая и тестовая выборки не пересекаются»
  решается тривиально: обучающей выборки нет вовсе. Стоимость обучения = 0 по построению;
  стоимость инференса меряется (время и память на ход).
- Если MCTS окажется конкурентным, следующим шагом можно добавить обучаемый value-prior
  вместо случайного rollout — это отдельная задача.

## Протокол (зафиксирован ДО запуска)

Протокол записан в этот файл отдельным коммитом **до** реализации и прогонов. Менять его
задним числом, глядя на результаты, нельзя: любые изменения — только новой секцией «Отклонения
от протокола» с причиной.

### Кандидат и baseline

- **Кандидат:** UCT-MCTS (`tools/mcts/mcts.js`): UCB1 с `c = 1.4`, расширение по одному ребёнку,
  случайный rollout с ограниченной глубиной и терминальной оценкой по разнице очков
  (`tanh(diff / 3)`), обратное распространение со сменой знака по ходящему (учёт дополнительного
  хода за захват — по фактическому `current` после хода, а не по чётности).
  Финальный ход — ребёнок корня с максимальным числом посещений.
- **Baseline:** замороженный `Engine.searchMove` с весами `tools/bench/baseline/weights.v1.json`,
  сложность `normal`, детерминированный лимит узлов через `makeSearchPlayer` (как в A07).

### Бюджеты (равные)

1. **Узлы:** бюджет кандидата задаётся в тех же «узлах», что `nodeLimit` baseline: одно применение
   хода к позиции поиска (в дереве или в rollout) = один узел. Основной бюджет: `nodeLimit = 300`
   на small (как пробный отчёт A07).
2. **Время (вторичная метрика):** фиксируется среднее время хода обоих ботов (`moveMs.p50/p95`).
   Если кандидат при равных узлах тратит существенно больше времени, это указывается отдельно,
   вывод о силе «при равном времени» без отдельного прогона не делается.

### Выборка

- Новый корпус `tools/bench/corpus/openings.b06.json`, генерируется
  `node tools/bench/benchmark.js --gen-corpus tools/bench/corpus/openings.b06.json --seed 20240629`.
  Он не пересекается с корпусом v1 (другой seed), и его сплит `test` раньше нигде не использовался
  (в т.ч. в подборе весов `train-bot.js` и в B05).
- Измеряется сплит `test`, поле `small`, все три набора правил корпуса, 1 прогон (исходные дебюты).
  Каждый дебют играется **парой** (кандидат за seat 1 и за seat 2).
- Ограничение по времени выполнения среды (300 с на команду) учитывается дроблением прогона
  на партии дебютов (`--from/--count`), а не сокращением протокола.

### Метрика и критерий

- **Основная метрика:** score кандидата против baseline (W = 1, D = 0.5, L = 0) по парам.
- **W/D/L** по партиям и по парам.
- **95% ДИ с учётом парности:** bootstrap по парам (кластер = пара одного дебюта;
  `bootstrapPairs` из `tools/bench/benchmark.js`), 10000 ресэмплов, seed 29.
- Кандидат считается **не слабее** baseline, если нижняя граница ДИ ≥ 0.5, **сильнее** — если > 0.5
  (критерий A07). Иначе результат отрицательный или неопределённый — и так и записывается.
- **Корректность:** ноль нелегальных ходов кандидата (`InvalidMoveError`) — иначе прогон невалиден.

### Стоимость

- Обучение: 0 (модели нет). Размер «модели»: 0 байт параметров; указывается размер кода модуля.
- Инференс: `moveMs.p50/p95`, итоговое число узлов на ход, прирост `heapUsed` за ход
  (`process.memoryUsage()` до/после, грубая оценка), максимальный размер дерева (число узлов дерева).
