# S5. Монитор опасных групп — только наблюдение (issue #59)

Шаг S5 дорожной карты `docs/MONITOR_ROADMAP.md`, п. 6 Плана. Монитор не меняет ходы бота. Партия проигрывается по записи, а монитор только смотрит на позиции. Отчёт сам проверяет, что узел после расчёта не изменился.

## Файлы

- `tools/bench/monitor.js` — признаки: `monitorPosition(node, p, opts)`, правила тревоги `RULES`, функция `alarmOf(res, rule)`.
- `tools/bench/monitor-report.js` — отчёт по таймлайну партий корпуса.
- `test/monitor.js` — синтетические позиции. Тест входит в `npm test`.
- `tools/bench/reports/s5-monitor-dev.json`, `tools/bench/reports/s5-monitor-holdout.json` — сохранённые отчёты.

Запуск:

```
node tools/bench/monitor-report.js --split dev [--timeline] [--json out.json]
node tools/bench/monitor-report.js --split holdout
```

Параметры: `--min-loss` (по умолчанию 1 точка), `--lead` (5), `--horizon` (10), `--no-twomove`, `--game id`.

## Признаки

Признаки считаются для каждой группы бота. Группа — живые точки, связанные по 8 соседям.

| Признак | Как считается |
|---|---|
| `cost` — стоимость окружения | Минимальное число ходов противника, после которых хотя бы одна точка группы окажется в области, отрезанной от края. Используется минимальный вершинный разрез (max-flow с расщеплением вершин) **от каждой точки группы отдельно** до края. Противник может занимать только пустые клетки, его стены уже стоят, точки и территорию бота он занять не может. Поэтому край обрабатывается по правилам `runCaptures`: точка на краю или связанная с краем 4-цепочкой не захватывается (`Infinity`), а остальные точки той же группы считаются отдельно, как захватываемые подмножества. Группа у края больше не считается безопасной целиком: это недостаток «разреза до края» из Плана. Разрез больше 6 не ищется. |
| `ringProgress` — прогресс кольца | Для лучшего разреза: `walls / (walls + cut)`. Здесь `walls` — стены противника на границе отрезаемой области, `cut` — клетки разреза, то есть недостающие клетки кольца. |
| `capture` | Сколько живых точек бота попадает в отрезанную область. |
| `size`, `exits` | Размер группы и число свободных клеток, 4-соседних с группой. |
| `twoMove` | `twoMoveThreat(node, opp)` из #55: сколько очков противник берёт двумя ходами подряд. |
| `tempo` | `own` или `opp` — чей ход. |

## Методика

- Таймлайн: позиция после **каждого хода бота**, то есть ход противника — худший момент для бота.
- Взятие — ход противника, пленивший не меньше `--min-loss` точек бота.
- `lead` взятия — сколько позиций подряд перед взятием тревога горела на пленённых точках (или на всю позицию для позиционных правил). Считается и последняя позиция перед взятием. Значит, `lead >= 5` — тревога горит с позиции после 5-го хода бота до взятия, включая его последний ход. Взятие **предупреждено**, если `lead >= 5`. Критерий «в большинстве потерь» означает долю предупреждённых больше 0.5.
- Ложная тревога — позиция с тревогой, после которой за 10 ходов бота (`--horizon`) ни одна отмеченная точка не пленена (для позиционной тревоги — не было ни одного взятия). Норма: не больше 1 на 10 ходов бота.
- Пороги правил заданы **до** первого прогона по корпусу и не менялись:

| Правило | Условие |
|---|---|
| `cost` | `cost <= 2` |
| `ring` | `ringProgress >= 0.75` |
| `exits` | группа не меньше 2 точек и не больше 1 выхода |
| `twoMove` | `twoMoveThreat >= 2` |
| `combined` | `cost <= 2` или `twoMoveThreat >= 2` |

## Результаты

dev — 2 партии (`issue52-r02-g0` small, `issue52-r02-g2` medium), 89 ходов бота, 12 взятий. holdout — 1 партия (`issue52-r02-g3` medium), 53 хода бота, 12 взятий.

| Правило | dev: предупреждено | dev: ложных на 10 ходов | holdout: предупреждено | holdout: ложных на 10 ходов | Итог |
|---|---|---|---|---|---|
| `cost` | 4/12 (0.33) | 2.70 | 5/12 (0.42) | 1.51 | не прошёл |
| `ring` | 0/12 | 0 | 0/12 | 0 | не прошёл: слишком поздно |
| `exits` | 0/12 | 0 | 0/12 | 0 | не прошёл: почти не срабатывает |
| `twoMove` | 6/12 (0.50) | 0.45 | 3/12 (0.25) | 0 | не прошёл: мало предупреждений |
| `combined` | 9/12 (0.75) | 1.35 | 6/12 (0.50) | 1.51 | не прошёл: ложные тревоги |

Время на позицию:

| | dev: среднее / p95 | holdout: среднее / p95 |
|---|---|---|
| дешёвые признаки (группы, разрезы, кольцо, выходы) | 0.34 / 0.81 мс | 0.41 / 1.40 мс |
| `twoMoveThreat` | 15–24 / 27–37 мс | 34–50 / 52–89 мс |

Цифры времени взяты из двух прогонов в Codespace. При `--min-loss 3` на dev `twoMove` проходит (4/7, 0.9 ложных на 10 ходов), но это смена определения после просмотра данных, поэтому в итог не идёт.

## Выводы

1. **Ни один признак не прошёл все три критерия.** По правилу issue такие признаки заменяются, а не подгоняются по порогам.
2. Дешёвые признаки укладываются в «единицы миллисекунд». `twoMoveThreat` в критерий времени не укладывается: на medium p95 доходит до 89 мс.
3. `ring` и `exits` срабатывают за 1–3 хода до взятия. Самостоятельными сигналами они не годятся, их можно оставить только как поля отчёта.
4. `cost <= 2` срабатывает рано, но даёт много ложных тревог: малую стоимость имеют и группы, которые противник не атакует.
5. `twoMove` даёт мало ложных тревог, но на коротких атаках (взятия 1 точки) не предупреждает заранее.

## Holdout уже использован

Отчёт по `holdout` (`issue52-r02-g3`) просмотрен в этом шаге. Признаки-замены, построенные по этим результатам, на нём проверять нельзя: нужна новая партия в `holdout` (по манифесту новые партии попадают туда по умолчанию).

## Признаки-замены (следующая итерация, проверять на dev, затем на НОВОМ holdout)

- `cost` с учётом темпа и атаки: тревога, если `cost` не больше числа ходов, которые противник успевает сделать подряд за счёт вынуждающих угроз. Нужен счётчик вынуждающих ходов противника в регионе разреза.
- Изменение `cost` во времени: тревога при падении стоимости на 2 и больше за ход противника вместо абсолютного порога. Это отсекает группы, которые не атакуют.
- Локальная версия `twoMoveThreat`: перебирать только клетки разреза и их окрестность радиуса 1, а не всё поле. Цель — уложиться в единицы миллисекунд.

Порог для каждой замены фиксируется до прогона.
