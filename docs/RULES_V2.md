# Контракт правил «Точек» — версия v2 (классика)

Статус: **согласовано автором** в issue #6 («Целевые правила классические. Все пункты, где v1 расходится с классикой, подлежат исправлению»).
Реализация: `gameEngine.js` (один модуль для Node и браузера). Эталоны: `test/fixtures/rules-v2.json`, тесты: `test/rules.js`.
Предыдущее поведение (v1) заморожено в `baseline/gameEngine.v1.js`, см. `docs/BASELINE_V1.md`.

## Состояние клетки
- `stone[y][x]` — цвет поставленной точки (0 — пусто), не меняется после постановки.
- `dead[y][x]` — владелец окружения, в котором точка пленена (0 — точка живая). Для пленной точки `dead` ≠ `stone`.
- `territory[y][x]` — владелец окружения пустой клетки (0 — нейтральная). **Очков не даёт.**

## Правила
1. **Окружение.** После хода игрока P ищутся четырёхсвязные области, не являющиеся «стеной» P (живые точки P, а также клетки, уже под контролем P). Область захватывается, если она **не касается края** и содержит **хотя бы одну живую точку противника**. Пустое окружение без точки противника не захватывается.
2. **Счёт.** Очко даёт только пленённая точка противника (`stone` = противник, `dead` = P). Пустые клетки и свои точки внутри контура очков не дают. Счёт всегда вычисляется из доски (`computeScores`), поэтому перезахваты и освобождения учитываются автоматически.
3. **Освобождение / перезахват.** Если внешний контур P окружает всё кольцо противника вместе с ранее пленённой точкой P, камни кольца становятся мёртвыми (`dead = P`, очки P), а своя точка P снова живая (`dead = 0`): очков за неё никто не получает, противник теряет очко за неё.
4. **Самоубийство.** Точка, поставленная в область, уже окружённую противником (`territory` = противник), сразу становится мёртвой: очко получает противник. Если сам ход замыкает собственный контур игрока, приоритет у его окружения. Ход в собственную окружённую пустую клетку запрещён (`illegal-cell`).
5. **Дебют.** Первые два хода партии (для любого `firstPlayer`) — только в центральной зоне 4×4 (`getOpeningZone`).
6. **Очередь.** После хода очередь переходит к противнику. При `extraTurnOnCapture` ход, пленивший хотя бы одну точку противника, оставляет очередь за ходившим (кроме завершающего хода). Освобождение/территория/самоубийство дополнительный ход не дают.
7. **Окончание.** После хода: полное поле, достигнутый активный порог очков (`targetScore > 0`) или заполнения (`0 < targetFillPercent < 100`, считаются точки и окружённые пустые клетки). `winner` — по счёту (0 — ничья), `current` на завершающем ходе остаётся за ходившим. `endNow()` завершает без дополнительной заливки.
8. **Отмена.** `undoLastMove()` полностью откатывает доску, счёт, очередь, счётчик точек; запрещена после окончания партии и при `undoAllowed: false`.
9. **Нелегальный ход** (`game-over`, `not-your-turn`, `illegal-cell`) не мутирует состояние.

## Известное ограничение бота
Поиск бота (`generateCandidates`/`quickScore`/`alphaBeta`) не рассматривает ходы в клетки с `territory ≠ 0` и моделирует ходы только через `runCaptures`. Поэтому бот никогда не выбирает самоубийство, что для него выгодно. Обратное ограничение: бот не учитывает, что соперник может пойти в его окружение. На легальность и счёт партии это не влияет, поскольку их считает `applyMove`.

## Отличия от v1
| Пункт | v1 (baseline) | v2 |
|---|---|---|
| Счёт | очки за пленные точки **и** пустые клетки | только пленные точки противника |
| Своя пленная точка в новом контуре | `dead = освободивший`, +1 очко ему | `dead = 0`, очков нет, противник теряет очко |
| Ход в окружение противника | клетка запрещена (`territory ≠ 0`) / захват не проверяется | разрешён, самоубийство: точка мертва, очко противнику |
| Доп. ход | при любом изменении области | только при пленении точки противника |
