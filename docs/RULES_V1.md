# Контракт правил tochki-rules-v1

Статус: **фиксация существующего поведения, ожидает согласования автора**
в [issue #6](https://github.com/mlaa4ml/tochki-multiplayer/issues/6).
Источник: `gameEngine.js` ревизии `4bfab9f` (main при начале A01).
Это не правила го. A01 не меняет игровую семантику. Изменение спорных
пунктов требует решения автора, новой версии контракта и новых фикстур;
старые эталоны и baseline нельзя переписывать под эксперимент.

## Доска и захват

Координаты `(x,y)`, массивы `[y][x]`, начало в левом верхнем углу.
Значения слоёв — 0 (нет), 1, 2 (места игроков).
`stone` — исходный цвет поставленной точки, никогда не удаляется захватом.
`dead` — **владелец захвата**, не исходный цвет и не boolean.
`territory` — владелец захваченной пустой клетки.
Стена игрока: его живая точка (`stone=p, dead=0`), `dead=p` или
`territory=p`. `cellOwner` отдаёт приоритет dead, затем territory, затем stone.

`runCaptures` ищет четырёхсвязные области НЕ-стен ходившего игрока.
Диагонального прохода нет: четыре ортогональные точки вокруг центра
уже замыкают центр. Область, содержащая клетку на краю доски, не захватывается.
Край не заменяет стену. Для захвата нужна хотя бы одна **живая**
(`dead=0`) точка соперника внутри; пустое окружение очков не даёт.

В захваченной области все занятые клетки получают `dead=p`, все пустые —
`territory=p`. Захват не меняет stone. Захваты проверяются только за
ходившего: вход в пустое окружение противника не запускает заливку за него.
Контроль сохраняется, автоматического пересчёта/освобождения нет.

### Перезахват и «освобождение» — спорная семантика v1

Большой внешний контур может забрать область с чужими dead/territory,
если внутри есть живая точка соперника. Предыдущее владение снимается,
очки переходят новому владельцу. Ранее пленённая своя точка тоже получает
`dead=p`, а НЕ `dead=0`: она остаётся неживой в терминах движка,
является своей стеной и даёт очко. Область только с мёртвыми точками
противника не захватывается. Эти факты зафиксированы, не объявлены
идеальными правилами и не «исправлены» без согласия автора.

## Матч, легальность и очередь

Размеры: small 12×10, medium 16×12 (default), large 22×16.
Неизвестный sizeKey заменяется medium. `firstPlayer` равен 2 только
для числового 2, иначе 1. `extraTurnOnCapture` включается только
строгим true; `undoAllowed` отключается только строгим false.

Первые **два поставленных хода партии**, а не два хода каждого игрока,
должны быть в центральной зоне 4×4. Для small это x=4..7, y=3..6;
medium x=6..9,y=4..7; large x=9..12,y=6..9.
После них разрешена любая свободная клетка.
Координаты должны быть целыми числами в пределах доски; stone и territory
в клетке должны быть нулевыми. На чужом ходу нельзя ставить точку.
Порядок отказов applyMove: game-over, not-your-turn, illegal-cell.
Отказ не изменяет доску, очередь, историю, счёт или возможность undo.

После успешного хода проверяется захват. Каждый элемент gained добавляет
одно очко игроку, а при prevOwner другого игрока отнимает одно у него
(с нижней границей 0). Пустая территория учитывается наравне с пленённой
точкой. Затем проверяется конец; если конца нет, gained.length>0 и
extraTurnOnCapture=true оставляют очередь игроку, иначе очередь меняется.
gained включает `{x,y,prevOwner}`. Порядок списка — деталь обхода, а не правило.

## Окончание

- Полное поле: у каждой клетки ненулевой stone ИЛИ territory.
- targetScore: floor с ограничением 0..9999, default 0; активен при >0.
  Матч заканчивается, когда хотя бы один счёт >= порога.
- targetFillPercent: только number (не NaN), иначе 100; floor и ограничение
  0..100. Активен строго между 0 и 100. Порог клеток:
  `ceil(rows*cols*targetFillPercent/100)`. Занятость — stone ИЛИ territory,
  без двойного счёта. 0 и 100 выключают этот порог, но не полное поле.
- Проверки выполняются после успешного хода. Если матч заканчивается,
  current остаётся за ходившим; extraTurn=false.
- endNow завершает немедленно по текущему счёту, без захватов и смены очереди.
- winner: 1/2 при большем счёте, 0 при равенстве; в незавершённом applyMove
  winner=null. В getSnapshot поля winner нет: это поле результата завершения.
- Повторный endNow и любой ход после конца возвращают game-over.

## Undo и снимки

undoLastMove восстанавливает три слоя, счёт, очередь, счётчик точек,
последние ходы обоих игроков и удаляет последнюю запись moveLog.
Можно повторять undo, пока есть история; требуется незавершённая партия
и undoAllowed. Отказы: undo-disabled (приоритет), game-over, nothing-to-undo.
Протокол согласия соперника не является частью чистого движка.
getSnapshot копирует слои и данные матча; getMoveLog возвращает копию
массива, но не глубокую копию его объектов — это не API импорта позиции.

## Эталоны и проверки

`test/fixtures/rules-v1.json` — ручные ожидаемые позиции и последовательности,
не снимки, автоматически объявленные правильными самим движком.
Низкоуровневые позиции проверяют runCaptures; последовательности начинаются
с createMatch и проверяют взаимодействие правил. Формат — тестовый корпус,
не новый формат пользовательского replay (это отдельная задача A02).

Команда чистых тестов: `npm run test:engine`. Она выполняет одинаковый корпус
через Node require и браузерную UMD-ветку window/self.TochkiEngine в изолированной
VM без module/require. Это проверка браузерного API, не UI/e2e браузера.
Общая регрессия: `npm test` на Node 24.x после `npm ci`.
Замороженный контрольный соперник описан в [BASELINE_V1.md](BASELINE_V1.md).
