# Точный replay v1 (A02)

`gameEngine.js` записывает историю на границе `createMatch()`, а `replay.js`
проверяет и проигрывает её без SQLite, DOM, сети и вызовов бота. Это единый
контракт для сервера, CLI, будущих offline-импорта/экспорта (B03) и наборов
позиций/обучения (A07). Полноценный replay UI и восстановление комнат после
рестарта сюда не входят.

## Формат

JSON-объект содержит **только** следующие поля:

- `format: "tochki-replay"`;
- `version: 1` — версия схемы;
- `engineVersion: "tochki-rules-1"` — версия семантики правил. При изменении
  правил требуется новая версия и явная поддержка проигрывателем, а не
  молчаливая интерпретация старых ходов по новым правилам;
- `board: {sizeKey, rows, cols}` — один из размеров `Engine.SIZES`, размеры
  должны точно совпадать с указанным ключом;
- `rules: {targetScore, targetFillPercent, scoreRuleActive, fillRuleActive,
  totalCells, extraTurnOnCapture, firstPlayer, undoAllowed}` — все настройки
  исходной партии, включая первого игрока и право отмены. Производные поля
  не игнорируются: `totalCells = rows * cols`, `scoreRuleActive = targetScore > 0`,
  `fillRuleActive = targetFillPercent > 0 && targetFillPercent < 100`;
- `metadata: {botVersion, weightsVersion, seed, budgets, weights}` — версии
  алгоритма/весов, seed, бюджеты и фактические веса, когда известны.
  Неизвестные значения обозначаются `null`, не придумываются;
- `events` — упорядоченный массив событий, в том числе отменённых ходов.

Версии ботов/весов — непустые строки до 128 символов или `null`. Встроенные
идентификаторы: `tochki-ab-1`, `tochki-weights-1`. `seed` — uint32 или `null`.
`weights` — `null` либо объект с четырьмя конечными числами `potential`,
`cohesion`, `stones`, `liberty` (абсолютное значение не более 1 000 000).
`budgets` — `null` либо объект с необязательными целочисленными полями
`radius`, `candidateCap`, `timeLimit`, `maxDepth`, `branchWide`, `branchMid`,
`branchNarrow`, `quiescenceExt`, `nodeLimit`, каждое в диапазоне 0..1 000 000 000.

События:

```json
{"type":"move","player":1,"x":4,"y":3}
{"type":"undo"}
{"type":"end","reason":"manual","winner":0,"scores":{"1":0,"2":0}}
```

- `move`: игрок 1 или 2, целые координаты внутри поля. Проверяются очередь,
  дебютная зона, занятость/территория клетки и остальные правила движка.
  Опциональное `decision` содержит те же обязательные поля, что `metadata`,
  плюс опциональное `difficulty` (`normal`, `strong`, `train`, `custom`).
  Сервер записывает туда фактические веса/бюджеты каждого решения бота
  (веса могут обновляться между ходами). Seed текущего бота неизвестен —
  `null`. Replay воспроизводит принятые ходы, **не** обещает повторного
  получения того же решения при новом запуске поиска.
- `undo`: отмена ровно последнего неотменённого хода, со всеми слоями
  состояния, счётом и очередью; допустима только если разрешена правилами
  и есть что отменять. События запроса/согласия WebSocket не нужны для
  воспроизведения: сохраняется только реально выполненная отмена.
- `end`: `reason` равен `manual`, `rule` или `abandoned`; `winner` — 0 (ничья),
  1 или 2; `scores` должны совпадать с результатом проигрывания. После
  терминального хода обязательно немедленное `end` с причиной `rule`.
  Ручное окончание соответствует `endNow()`, заброшенность —
  `endNow('abandoned')`. После `end` событий быть не может.

Незавершённый корректный префикс допустим. Отменённые ходы остаются в
`events`, но не в `getMoveLog()` восстановленной партии. Терминальные
ходы автоматически дописывают событие `end`; вызывающий код не должен
добавлять второе. Неуспешные операции событий не создают.

## Проверка и атомарный импорт

```js
const Engine = require('./gameEngine.js');
const Replay = require('./replay.js');

const active = { match: Engine.createMatch({ sizeKey: 'small', firstPlayer: 2 }) };
active.match.applyMove(2, 4, 3);
const json = Replay.stringify(active.match);
const restored = Replay.play(json); // отдельная партия, исходную не меняет
Replay.importInto(active, json);    // active.match заменяется только после проверки
```

`getReplay()` возвращает отделённую копию объекта; `stringify(match)`
дополнительно проверяет экспорт и возвращает JSON. `play(input)` принимает
JSON-текст или JSON-объект, возвращает новый `Match`. `importInto(holder, input)`
сначала полностью выполняет `play`, затем присваивает `holder.match`.
При ошибке текущая партия не меняется. Это API для владельца локальной
партии, а не для замены живой серверной комнаты вместе с сокетами/таймерами.

Для offline загрузить `gameEngine.js`, затем `replay.js` обычными `<script>`
из локального комплекта файлов. API доступны как `TochkiEngine` и
`TochkiReplay`; схемы и проверки те же, что в Node. Сетевой UI импорта
в этой задаче не добавлен.

Пример CLI-проверки файла из корня репозитория:

```sh
node -e 'const fs=require("fs"), r=require("./replay.js"); console.log(r.play(fs.readFileSync(process.argv[1],"utf8")).getSnapshot())' match.json
```

Неизвестные поля/версии, отсутствующие правила, нецелые числа, неверные
размеры, нелегальные события и несогласованный итог отклоняются с `Error`
и префиксом `Replay:`; для событий указан индекс (с нуля).
Ограничения: 2 MiB UTF-8 после сериализации, не более 4096 событий,
глубина входа не более 12 и не более 150000 посещённых значений.
JSON-текст дополнительно ограничен по длине до разбора. Объектные входы
проверяются на циклы, не-JSON-значения и аксессоры. `targetScore` — целое
0..9999, `targetFillPercent` — целое 0..100, `firstPlayer` — 1 или 2;
флаги должны быть boolean. Это ограниченный импорт, не произвольный
интерпретатор будущих схем.

## Сервер, SQLite и legacy

При открытии БД идемпотентная транзакционная миграция добавляет в `games`
`replay_status TEXT NOT NULL DEFAULT 'legacy'` и `replay_json TEXT`.
Существующие строки остаются `legacy` с NULL-реплеем: их исходные
`firstPlayer`, `extraTurnOnCapture` и события отмены восстановить нельзя.

Новые партии сохраняют исходный заголовок уже при создании. При каждом
ходе сохраняются аналитическая строка `moves` и актуальный replay в одной
транзакции; undo сохраняет обновлённый поток, завершение — replay и итог.
При удалении недоигранной комнаты сохраняется `end/abandoned`; такие
партии, как прежде, не считаются победами/поражениями.

`GET /api/games/:code`, `getGameByRoomCode()` и
`getFinishedGamesForTraining()` возвращают дополнительно:

- новый лог: `replay: {status: "exact", exact: true, data: <replay v1>}`;
- старый лог: `replay: {status: "legacy", exact: false, reason: "..."}`.

`exact` указывает происхождение полной записи, а не отменяет проверку
входа через `Replay.play`. `game` содержит `replay_status`, но не дублирует
большой `replay_json`. Старые `game`/`moves` сохраняются для статистики и
совместимости. **Таблица moves — не точный replay**: в ней остаются
отменённые ходы. Учебный CLI берёт дебюты только из проверенных exact-логов,
из эффективного `getMoveLog()` с исходными правилами. Legacy пропускаются,
отсутствующие параметры не угадываются.

## Проверки

`npm test` включает:

- `test/replay.js`: export/import, оба первых игрока, оба режима очереди
  после захвата, отмена захвата, ручной/автоматический конец, строгие
  отказы и атомарность, исполнение того же codec в browser VM;
- `test/replay-db.js`: миграция дисковой старой схемы, legacy-чтение,
  повторное открытие БД, сохранность нового exact-лога;
- `test/undo.js`: реальные WebSocket-ходы, захват, согласованная отмена,
  ручной конец и сравнение сохранённого replay с серверным snapshot.
