# A08: сохранение тактических и стратегических кандидатов

Ветка: `openai-gpt-6-1-sol-issue-13`.

## Изменения

- До локального ранжирования/beam выполняются переходы общим движком правил:
  реальные захваты, немедленные победы и ответы, устраняющие все немедленные
  угрозы соперника. Учитываются пороги окончания и дополнительный ход.
- Для проверки захвата используется топологический предварительный фильтр
  (не менее двух соседних стен, включая диагонали), а не оценка liberties.
  На завершающем заполнении проверяются все легальные клетки.
  `tacticalFullScan: true` отключает этот фильтр.
- Сохраняются разрывы контуров, представители кратчайших путей к краю
  через дополнение стен противника и представители девяти секторов поля.
- Обязательные кандидаты не обрезаются обычным beam. Стратегические
  представители также резервируются до заполнения оставшегося beam.
  Итоговый набор может превышать cap; ограничителем остаётся бюджет поиска.
- Продления используют тот же тактический анализ, а не только локальные
  liberties/первые десять ранжированных ходов.
- Во время тактического перебора проверяется deadline. Прерванная генерация
  не считается завершённым поиском: сохраняется механизм abort/fallback A04.
  Лимит узлов по-прежнему считает узлы поиска, а не отдельные проверочные
  переходы генератора. Поэтому одинаковый nodeLimit НЕ означает одинаковое
  время; для интерактивной игры важен timeLimit.
- Диагностика генерации включается через `generationDiagnostics: true`,
  чтобы не нарушать детерминированность обычного trace.

Флаги `tactical: false` и `strategic: false` позволяют независимо отключать
две составляющие без смены весов или глубины. Глобальная оценка и веса
не изменялись.

## Корректность

`test/candidates.js` сравнивает набор до поиска с независимым полным перебором
легальных переходов: захват, единственная защита, пороговая победа,
extraTurnOnCapture, заполнение и дальний фланг. Проверяется сохранность
при cap 1/3/10 и переполнение мягкого beam. Дополнительно проверяются
детерминированные достижимые позиции 5×5 с разными правилами.

В Codespaces на Node 24 пройдены candidates, replay, replay-db, rules,
transition, search, e2e, auth, names, gamelog, rooms, train, undo и bench.
Search-тесты включают управляемые часы, распространение abort, Worker
и детерминированный лимит узлов.

Единый `npm test` был остановлен лимитом команды 300 секунд внутри
offline-session, без упавшего assert. Первые 16 offline-проверок успели
завершиться успешно. Две оставшиеся проверки
«бот–бот без доп. хода чередует игроков» и
«пауза в бот–бот не разрешает лишний ход, start продолжает»
выполнены отдельно с неизменёнными телами тестов через фильтрацию списка
в памяти (Module._compile), обе прошли. Напечатанное этим фильтрованным
запуском `18/18 passed` — особенность исходного счётчика, а не число
выполненных в нём проверок. Остальные группы после offline-session
запускались отдельно. Полного непрерывного успешного `npm test` не заявляем.

## Измеренный ablation и независимые пары A07

Источник: `tools/bench/reports/a08-ablation.json` (содержит commit и Node).
Повторение, Node 24, после `npm ci`:

```sh
A08_NODES=100 A08_PAIRS=2 A08_MOVES=100 A08_SAMPLES=2 \
  node tools/bench/a08-ablation.js /tmp/a08-ablation.json
```

Это ограниченный smoke, а не полный bench: normal, два дебюта small/test,
смена цвета в каждой паре, одинаковые baseline-веса, соперник с обеими
добавками выключенными. Для каждого варианта проведено четыре партии;
ошибок воспроизведения и усечённых партий нет.

| Вариант | Пропуски эталонных ходов | Генерация отдельно p50/p95, мс | Ход p50/p95, мс | Узлы p50/p95 | Генерация за поиск p50/p95, мс | Score [CI95] |
|---|---|---|---|---|---|---|
| base | 0/6 | 0.031 / 0.091 | 6.83 / 22.79 | 82 / 93 | 0.86 / 2.13 | 0.50 [0.50, 0.50] |
| tactical | 0/6 | 0.088 / 0.454 | 4.01 / 375.64 | 81 / 84 | 1.90 / 293.12 | 0.50 [0.50, 0.50] |
| strategic | 0/6 | 0.065 / 0.121 | 2.89 / 9.86 | 100 / 100 | 0.66 / 2.21 | 0.25 [0.25, 0.25] |
| both | 0/6 | 0.101 / 0.472 | 10.29 / 268.45 | 100 / 100 | 4.16 / 235.22 | 0.50 [0.25, 0.75] |

Квантили времени поиска собраны на шести фиксированных позициях, по два
повтора; это не распределение задержек всех ходов парных партий.
Пропуски относятся к обязательным ходам на этих шести позициях; дальний
стратегический фланг дополнительно проверяется отдельным assertion.

**Вывод:** сохранность согласованного корпуса проверена, но уменьшение
пропусков относительно base на этих шести позициях не продемонстрировано:
base уже имел 0/6. Усиление бота не установлено. Две пары дают слишком
мало независимых наблюдений; даже вырожденный bootstrap CI не является
доказательством равной силы. Вариант strategic проиграл на этом smoke.
У both существенно вырос p95 времени при одинаковом nodeLimit, основная
стоимость — повторный анализ защиты внутри дерева. Это ограничение
реализации и причина не трактовать nodeLimit как временной бюджет.
Для интерактивного режима сохраняются deadline и fallback A04.

Числа пользователя из issue для другой ветки
`anthropic-claude-opus-5-5-default-issue-13` не являются измерениями этой
реализации и в таблицу не включены.
