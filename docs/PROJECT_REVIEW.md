# Анализ проекта Tochki Multiplayer

## 1. Обзор архитектуры и компонентов
Проект представляет собой онлайн-игру «Точки» с клиент-серверной архитектурой на Node.js:
- **`server.js`**: Главный серверный файл на базе `express` и `ws` (WebSockets). Управляет комнатами, веб-сокет соединениями, матчмейкингом, переподключением, авторизацией и REST API.
- **`gameEngine.js`**: Ядро игровой логики. Реализует правила игры «Точки» (построение цепей, окружение территорий, захват точек, определение победителя), симуляцию ходов и искусственный интеллект (бота).
- **`auth.js`**: Модуль регистрации, авторизации пользователей, проверки токенов сессий ихеширования паролей.
- **`db.js`**: Слой работы с базой данных на базе `better-sqlite3`. Управляет сохранением пользователей, сессий, партий, истории ходов и весов ботов.
- **`gamelog.js`**: Логгирование игровых событий и партий.
- **`public/client.html`**: Клиентская часть (Single-Page Application на HTML/JS/CSS), работающая через WebSockets с сервером.
- **`tools/train-bot.js`**: Инструмент для самообучения (self-play) и оптимизации весов эвристик бота.

## 2. Анализ текущей реализации бота
Текущий бот реализован в `gameEngine.js` (функции поиска ходов и оценки позиций).
- **Проблемы**:
  1. Ограниченный горизонт поиска и локальная оценка позиций: бот часто оценивает локальные выгоды (захват пары точек), не учитывая глобальную стратегию перекрытия свобод (либерти) и окружения больших территорий.
  2. Слабая модель прогнозирования целей: симуляция игры иногда сбивается при глубоких ветвлениях, а эвристические веса ($potential, $cohesion, $stones, $liberty$) подобраны эвристически и требуют качественной калибровки через самообучение.
  3. Отсутствие понимания терминальных целей матча (блокировка ходов соперника на дальних рубежах).

## 3. План дальнейших доработок
1. **Усиление бота**:
   - Расширение эвристической функции оценки за счет учёта связности цепей и давления на ключевые зоны.
   - Оптимизация алгоритма поиска (продуктивный minimax / alpha-beta прунинг с динамической глубиной).
   - Исправление и стабилизация скрипта самообучения (`tools/train-bot.js`), чтобы избежать сбоев при интеграции с SQLite в новых версиях Node.js.
2. **Бессерверная версия (Offline Lab)**:
   - Создать автономную версию клиента/движка на базе Web Workers, позволяющую запускать матчи человек-бот и бот-бот прямо в браузере без поднятия Node.js сервера. Это ускорит тестирование правил и отладку бота.
