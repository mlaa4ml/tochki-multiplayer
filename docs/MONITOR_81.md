# Монитор после #77: поиск реального прироста (issue #81)

Ветка: `anthropic-claude-opus-5-5-default-issue-81`. По умолчанию поведение бота не меняется: все новые режимы выключены. `test/root-first.js` проверяет значения по умолчанию и совпадение с базой при `monitor:false`.

## Что сделано

1. **Тактический набор из партий против человека** — `tools/bench/tactical-set.js`, набор `tools/bench/corpus/tactical.v1.json`.
   - Позиции отбираются логикой `--prefork` (#57). Берётся последний ход бота перед взятием у него не менее 4 точек, если после этого хода спасение ещё существовало (forkLoss4, 6 полуходов).
   - `rescue[]` — спасающие ходы. Позиция считается решённой, если ход бота входит в `rescue[]`.
   - Сборка инкрементальная (`doneGames`), потому что forkLoss4 дорогой: 30–85 с на партию.
   - Сейчас в наборе 3 позиции: `issue52-r01-g0@42`, `issue52-r01-g1@42`, `issue52-r02-g0@62`.
   - В корпус добавлен реплей владельца `tools/bench/corpus/human/tochki-replay-2026-11-05T09-56-32-902Z.json`. Его разбор не уложился в лимит команды codespace, поэтому его нужно досчитать (см. ниже).
   - Команды:
     - `node tools/bench/tactical-set.js --build [файлы]` — сборка набора;
     - `node tools/bench/tactical-set.js --configs base,static,fork --json out.json` — оценка.

2. **Гипотеза 1: ход-спасение подаётся в корень поиска.**
   - В `gameEngine.searchMove` добавлен `opts.rootFirst`: ходы из него ставятся первыми корневыми кандидатами.
   - В арбитре добавлен `rescueMode: 'root'`: повторный поиск, в котором спасения решателя идут в корне первыми, вместо подмены хода по `evaluateStatic`.
   - Флаг `rescuePartial` дополнительно подаёт ход решателя с частичной потерей группы.

3. **Гипотеза 2: ранняя тревога.** Флаги `alarmCostLarge` и `largeGroupSize` включают тревогу `cost <= 3` для групп от 6 точек.

4. **Детектор спасения по forkLoss4** (`forkRescue`, флаг стороны `fork`, конфигурация S8 `fork`). Сделан потому, что разбор набора показал: решатель S6 расходится с forkLoss4.
   - В `r01-g0@42` решатель «спасает» группу из 22 точек ходом 7,3, а реальное спасение — 8,5.
   - В `r01-g1@42` решатель не находит ход 4,8.

   Как работает детектор:
   - Для крупных тревожных групп считается потеря хода общего поиска на 6 полуходов.
   - Если потеря не меньше 3, перебираются клетки рядом с группой.
   - Играется ход, который теряет хотя бы на 3 точки меньше.
   - Ограничения: `forkTimeLimit` и `forkCap`. Диагностика пишется в `trace.arbiter.fork`.

## Результаты

### Тактический набор (strong, 3000 узлов)

Отчёт: `tools/bench/reports/tactical-81.json`.

| Конфигурация | Решено | Макс. время хода |
|---|---|---|
| base | 1/3 | 0.66 с |
| static (#77) | 1/3 | 2.0 с |
| root, root-large | 1/3 | 2.0 с |
| root-partial | 0/3 | 2.4 с |
| **fork** | **2/3** | 5.1 с |

`fork` — первый вариант, который решает больше позиций набора, чем база: он решает `r01-g0@42` ходом 8,5. Варианты `root*` прироста на наборе не дали.

### Парный матч `fork` против базы

Сыграна 1 пара из 20: пара 0, счёт 0:2 и 1:5, шард `out/s8-81/fork.0-1.json`. Время хода p95: 2.3 с у `fork`, 0.58 с у базы.

Одной пары для вывода мало. Матч на 20 пар не помещается в лимит codespace (около 100 с на пару), его досчитывает владелец. Если на 20 парах ci95.lo окажется ниже 0.5 из-за ухудшения, `fork` останется выключенным. Набор при этом остаётся инструментом для следующих вариантов.

## Что запустить локально

```
git checkout anthropic-claude-opus-5-5-default-issue-81
node tools/bench/tactical-set.js --build tools/bench/corpus/human/tochki-replay-2026-11-05T09-56-32-902Z.json
node tools/bench/tactical-set.js --build          # остальные партии корпуса (пропускает готовые)
node tools/bench/tactical-set.js --configs base,static,fork --json tools/bench/reports/tactical-81.json
node tools/bench/s8-ablation.js --config fork --from 1 --to 20 --pairs 20 --no-tactics --out-dir out/s8-81
node tools/bench/s8-ablation.js --table --out-dir out/s8-81
```
