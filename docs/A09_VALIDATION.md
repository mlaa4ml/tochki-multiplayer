# A09 (issue #14): связь области с краем вместо аналогии с го — валидация

## Что изменено

- **`computeGroupLiberties` / `libertyRisk`.** Код не менялся, поправлен комментарий. Liberties названы проверяемой эвристикой, а не правилом захвата. По правилам `runCaptures` захватывает область, если её путь к краю перекрыт стенами захватчика. Число соседних пустот этого не определяет. Фикстура: точка в углу с 0 liberties не захватывается.
- **Новый признак `computeEdgeEscape(state, rows, cols, player)`.** Он использует тот же критерий, что и `runCaptures`. Перебираются области из клеток, не являющихся стеной `player`, которые содержат живые точки соперника и ещё касаются края. Вклад области: `liveOpp / (1 + borderCells)`.
  - Узкий выход (мало клеток края) — высокая ценность закрытия.
  - Широкий выход — почти ноль.
  - Пустые области без соперника вклада не дают: они очков не приносят.
- **`evaluateStatic`.** Добавлен член `edgeDiff * weights.edgeEscape`. При отсутствии или нуле веса признак **не вычисляется**, поэтому цена и оценка по умолчанию не меняются.
- Правила игры не менялись. Терминальная победа по-прежнему обрабатывается поиском до статической оценки.

## Фикстуры (`test/eval-a09.js`, включён в `npm test`)

1. **Край с малым числом liberties без захвата:** 0 liberties, `runCaptures` ничего не захватывает.
2. **Замкнутая пустая область без очков:** счёт 0:0, `edgeEscape` = 0.
3. **Полезное окружение с противником:** 1 очко.
4. **Выход через узкий проход:** 0.5 против почти 0 у широкого. Закрытие прохода реально захватывает точку, после захвата признак равен 0.
5. **Бесполезная локальная плотность:** признак не меняется.
6. **Несколько фронтов:** вклад двух одинаковых фронтов ровно удваивается.
7. **Близкий порог окончания:** реальное пленённое очко оценивается выше давления формы даже при `edgeEscape = 20`. Дополнительно проигрывается настоящая партия `createMatch({ sizeKey: 'small', targetScore: 1 })`: окружение центральной точки даёт счёт 1:0 и `gameOver === true`. Терминальная победа наступает по правилам движка, а не по статической оценке.
8. **Выключенный признак:** оценка бит-в-бит совпадает с базовой.

## Решение и ограничения

- Заранее выбранный критерий A07: нижняя граница CI95 больше 0.5 и 0 ошибок. Он **не выполнен**. Это ограниченный прогон: 4 дебюта, 1 прогон, только small/normal. Рост силы не объявляется, признак **не включён по умолчанию** (`BOT_WEIGHTS.edgeEscape` отсутствует).
- Остальные признаки введены **по одному**: см. раздел «Шаги 2–5». Каждый выключен по умолчанию и проверен отдельно: фикстура, ablation, цена вычисления и парный A07.

## Шаги 2–5: признаки по одному

Все признаки выключены по умолчанию (вес отсутствует или равен 0). `evaluateStatic` получил необязательный параметр `ctx`; `alphaBetaSearch` передаёт в него узел поиска: очередь хода, счёт и правила.

- **`closeCost`** — стоимость закрытия/выхода, проверенная реальными правилами.
  - `closeInOneThreat` берёт области с живыми точками соперника, у которых выход к краю не шире 2 клеток.
  - На каждую пустую клетку края такой области ставится точка, затем запускается `runCaptures`.
  - Значение — максимум пленённых точек за 1 ход. Признак — разница своей угрозы и угрозы соперника.
  - Ограничение: внутренние коридоры (не на краю) не проверяются.
- **`captureRace`** — гонка захватов. Если обе стороны могут пленить за ход, преимущество получает тот, чей ход (`ctx.current`).
- **`phase`** — фаза партии. Вес потенциала территории снижается по мере заполнения доски.
- **`endgameScore`** — у порога окончания по очкам (до цели ≤ 2 очков) признаки формы демпфируются, остаётся итоговый счёт.

Фикстуры в `test/eval-a09.js`: 13/13 вместе с шагом 1. Полный `npm test` в Codespace на этой ветке завершается с кодом 0.

Условия:

Устойчиво видно следующее:
- `closeCost` заметно дороже остальных признаков из-за пробных `runCaptures`;

Ограничения A07:
- Объём мал: 4 дебюта и 1 прогон, то есть 8 партий на соперника.
- У closeCost, captureRace и phase W/D/L совпадают. Вероятно, в этих коротких партиях признаки почти не меняют ходы: гонки захватов и порог по очкам почти не возникают, а в корпусе `targetScore = 0`, поэтому `endgameScore` в A07 вообще не активируется.
- Для вывода нужен целевой корпус (узкие выходы, гонки, `targetScore > 0`) и полный прогон.
- Подбор веса `edgeEscape` и оптимизация поиска отложены: это B04 и B05.
- Для полного вывода нужен прогон большего объёма: `--runs 3`, sizes small,medium, difficulties normal,strong. Он не укладывается в лимит времени среды агента.
